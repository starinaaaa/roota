# Roota — памятка владельцу магазина

Эта памятка собирает ответы на вопросы о магазине в одном месте. По мере новых вопросов дополняем нужный раздел: что делать, где это находится, что проверено и что ещё требует проверки. Пароли, ключи и данные покупателей сюда не записываем.

Последнее обновление: 16 октября 2026 года.

## Где сейчас работает магазин

- Сайт: https://roota.moscow. Админка: https://roota.moscow/admin.
- Приложение: Next.js в Timeweb, 1 CPU / 2 ГБ RAM.
- Основная база: управляемый PostgreSQL Timeweb в Москве. Доступ к базе есть только у сервера.
- Фотографии: приватный Timeweb S3 в России. Готовые размеры фотографий сохранены.
- Вход в админку: Better Auth; пользователи и сессии находятся в PostgreSQL Timeweb.
- Платежи: Robokassa, рабочий режим. Настоящее уведомление о демо-оплате на основном домене проверено 16 октября; реального списания для проверки не было.
- Доставка: Ozon. Письма покупателям: UniSender Go.
- Старые тестовые клиенты, заказы, оплаты, подписки и очереди в рабочую базу не переносились. Остались четыре выбранные тарелки по 10 штук.
- Исходный Supabase и зашифрованная резервная копия сохранены для отката. Теперь также временно используется прежняя Edge Function для Telegram — это отдельно согласованное исключение, а не основная база магазина.

История переноса и восстановления: [Timeweb](docs/migration/TIMEWEB.md), [протокол проверок](docs/migration/VERIFICATION.md). Эти документы содержат историю этапов; текущие пользовательские настройки фиксируются в этой памятке.

## Как добавить категорию

В карточке нового или существующего изделия под полем «Категория» находится кнопка **«+ Добавить категорию»**.

1. Введите название, например «Вазы».
2. Адрес категории заполнится автоматически латиницей. Его можно исправить.
3. Нажмите **«Создать и выбрать категорию»**.
4. Категория сразу появится в списке и будет выбрана для текущего изделия. Заполненные поля и загруженные фотографии сохранятся в редакторе.
5. Сохраните само изделие обычной кнопкой.

Категория создаётся отдельно от изделия. Закрытие несохранённой карточки не удаляет уже созданную категорию. Адреса категорий должны быть уникальными; при совпадении редактор покажет ошибку. Добавление доступно только вошедшим администраторам. Эта доработка добавляет создание категорий; удаления, переименования и управления их порядком в интерфейсе пока нет.

## Что такое Better Auth

Это библиотека входа в админку, встроенная в сайт. Отдельный аккаунт на сайте Better Auth и отдельная подписка не нужны. Она проверяет пароль, создаёт защищённую сессию и позволяет выйти из аккаунта. Пароли хранятся в виде хешей, а не открытым текстом.

Открытая регистрация отключена. Доступ имеют только заранее созданные пользователи с разрешёнными email. Ограничены попытки входа; сессия действует 8 часов.

## Как добавить второй вход

Нужны отдельный email и отдельный пароль. Сейчас администратор добавляется разовой серверной настройкой: создать пользователя и включить его email в `ADMIN_EMAILS`. Кнопки приглашения пользователей в админке пока нет. У всех администраторов одинаковые полные права; отдельных ролей менеджера и редактора пока нет.

Пароль задаём через защищённое локальное окружение, а не в чате и не в Git. Технический инструмент: `scripts/migration/admin.ts`; существующие аккаунты он не перезаписывает. Сам по себе новый пароль PostgreSQL не является паролем входа в админку.

## Telegram: временная схема

16 октября повторная проверка из работающего приложения Timeweb показала таймаут подключения к `api.telegram.org:443` по IPv4 за 8 секунд. Ошибка возникает до проверки токена бота.

Владелец разрешил временно использовать уже существующую Supabase Edge Function `telegram-order-notification` как посредник. Она была фактически проверена через API управления: активна, версия 4, проверка JWT включена. Новый сервер для этого не покупается; исходные cron Supabase остаются выключенными.

Схема: **заказ в Timeweb → постоянная очередь Timeweb → прежний посредник → прежние чаты Telegram**. В тексте только номер, сумма, состояние оплаты/заказа и ссылка на закрытую админку. Имя, email, телефон и адрес покупателя туда не передаются. Технические ключи передаются только между серверами по HTTPS, не выводятся в браузер и логи.

Для этого используются ранее сохранённые токен бота, chat ID и серверный ключ посредника. Создавать нового бота или присылать ключ в чат не нужно. Если нужен другой чат, его нужно отдельно подключить к боту и настроить получателя.

Повторные события не должны создавать повторные отправки. Если ответ потерян или доставка получилась частичной, запись получает состояние «неизвестно» и автоматически не отправляется ещё раз. Подтверждение Telegram означает принятие сообщения сервисом, а не то, что человек его прочитал.

**Пока используется этот посредник, Supabase отключать нельзя.** После восстановления прямого доступа или переноса посредника можно убрать последнюю рабочую зависимость. Письма покупателям через UniSender от смены канала студии не меняются.

## UniSender: что осталось

Сохранены шаблоны, очередь, служебные письма о заказах, отдельные настройки маркетинговых писем, согласия, отписки и обработка статусов доставки. Служебные и маркетинговые сообщения используют разные проекты/ключи. Настройки отправки возвращены в рабочий режим; старые тестовые подписчики и очереди не перенесены.

Подтверждена доставка контрольного письма студии. Полный путь каждого вида покупательского письма на реальном заказе отдельно не проверялся: успешная отправка одного письма не доказывает все сценарии. После возврата Telegram сообщения о заказах студии направляются в Telegram; покупательские письма остаются в UniSender.

## Как готовить фотографии

Практический ориентир: JPEG в sRGB, длинная сторона около 2000–2400 px. WebP и PNG тоже поддерживаются. Старайтесь держать исходник в пределах 1–3 МБ, если качество позволяет; это рекомендация, не обязательное ограничение. Скриншоты и фотографии, пересланные мессенджером со сжатием, часто уже потеряли детали — увеличение размера их не восстановит.

Ограничения загрузки сайта: JPEG, PNG или WebP до 10 МБ; обработка ограничена 40 миллионами пикселей. HEIC непосредственно не поддерживается — перед загрузкой экспортируйте его в JPEG.

Вручную готовить восемь файлов не надо. При загрузке через админку сайт сохраняет оригинал и сам создаёт WebP шириной 160, 360, 480, 640, 960, 1440, 1920 и 2400 px. Маленькое исходное фото не растягивается. Браузер выбирает подходящий вариант под экран; фотографии ниже первого экрана загружаются лениво.

Загрузка и обработка нового исходника в админке и показ готового фото посетителю — разные процессы. Восемь вариантов создаются при загрузке, а не при каждом открытии каталога. Если положить файл прямо в S3, сайт сам не создаст карточку изделия и нужные размеры: загружайте фотографии через редактор.

## Замер фотографий и CDN — 16 октября

Проверены HTTP-запросы готовых размеров, без изменения фотографий и настроек CDN. Это замер с одного подключения, не мобильный браузерный тест и не сравнение с прошлой скоростью Supabase.

| Что проверено | Вес | Полная загрузка |
| --- | --- | --- |
| Четыре фото каталога, WebP 640 px | 32–49 КБ каждое | 0,5–1,1 секунды |
| Один пример WebP 360 px | 11,5 КБ | 0,32 секунды |
| То же фото 640 px через купленный CDN, первый запрос | 32 КБ | 0,55 секунды |
| То же фото через CDN, повторный запрос | 32 КБ | 0,077 секунды |

Ожидание первого байта через сайт составило около 0,17–0,24 секунды. Версии 640 px действительно имеют ширину 640 px. Для первого проверенного фото запросы 1440/2400 возвращают изображение шириной 960 px: увеличение исходника отключено. Наличие большого размера в адресе не добавляет детализацию маленькому исходнику.

Купленный CDN существует, связан с нужным бакетом, AWS-авторизация к приватному бакету включена. До контрольных запросов панель показывала 0 Б трафика. Сам сайт пока получает фотографии через свои `/media/...`, а не через этот CDN. Одно включение услуги в панели не переключает ссылки сайта.

Результат показывает, что подготовленные файлы уже небольшие, а CDN способен ускорить повторную отдачу. Он не обещает 77 мс каждому посетителю: результат зависит от региона, кеша и сети.

### Что делать для ускорения дальше

1. Подключить CDN именно к опубликованным фотографиям. В том же бакете есть черновики, поэтому нельзя автоматически открывать для раздачи все объекты.
2. Учитывать размер и версию картинки в ключе кеша. Для текущих адресов важны параметры `w` и `v`, иначе посетитель может получить неподходящий размер.
3. Настроить обновление кеша при изменении фото или публикации, затем проверить разные устройства и повторную загрузку.
4. Оставить готовые WebP и адаптивные размеры. Дополнительное сильное сжатие и покупка обработки изображений на лету пока не обоснованы.
5. Проверить уже реальную страницу в мобильном браузере: первое фото должно загружаться сразу, остальные — по мере необходимости.

В рамках текущей доработки CDN не перенастраивается, фотографии не пережимаются и тарифы не меняются.

## Известные ограничения производительности

Это краткая запись по уже известной архитектуре, не новый аудит и не список доказанных перегрузок.

- Готовое фото сейчас проходит через приложение: проверка публикации в базе → чтение из S3 → отдача посетителю. Это лишняя работа приложения на каждый некешированный файл.
- Пул рабочей базы ограничен двумя соединениями. Это защита базы; при одновременных запросах к нескольким фото и оформлению возможна очередь. Увеличивать пул без измерения нагрузки не следует.
- Приложение имеет 1 CPU и 2 ГБ RAM. Обработка больших новых фотографий и фоновые задачи делят его ресурсы с сайтом. При обычном показе готовых фотографий новые размеры не генерируются.
- Ozon, Robokassa, UniSender и Telegram — внешние сервисы со своими задержками. Медленный ответ расчёта доставки не означает медленный PostgreSQL.
- Публичный каталог кешируется; персональные корзины и заказы намеренно не используют общий кеш.
- Прежний нагрузочный тест выполнял HTTP-запросы без JavaScript. Его нельзя считать полным измерением скорости мобильного интерфейса.

## Что сохранилось после переезда

Сохранены структура и основная логика каталога/черновиков, остатков, резервов, оформления, оплат, возвратов, доставки, отзывов, писем и воронки. Изменились инфраструктура, система входа и запуск фоновых заданий. Не перенесена старая тестовая история. Telegram временно возвращается через прежний посредник по отдельному разрешению владельца.

Проверены критические транзакции, защита от повторов, админка, фотографии, корзина, расчёт доставки и настоящее демо-уведомление Robokassa на основном домене. Все сочетания реальных возвратов, отправлений и покупательских писем не объявляем проверенными. Выбор российского сервера сам по себе не доказывает полное соответствие 152-ФЗ; размещение и сроки хранения некоторых логов уточняются у провайдера.

## Для технической поддержки

Исходный код: https://github.com/starinaaaa/roota, рабочая ветка `main`. Пример переменных без секретов: `.env.example`. Для локального запуска: `npm ci`, затем `npm run dev` с закрытым локальным окружением. Изменения, показанные на сайте, должны быть развёрнуты в Timeweb: одно сохранение файла на компьютере не меняет рабочий магазин.

## Размеры текста

Шесть размеров публичного сайта находятся в начале `app/globals.css`, в блоке
`@theme`: `--text-caption` (14 px), `--text-ui` (16 px), `--text-copy` (18 px),
`--text-price` (24 px), `--text-section` (36 px), `--text-page` (56 px).
Меняйте значение в одном месте, чтобы обновить все элементы этой роли.
Например, `--text-copy: 1.25rem` даст 20 px на компьютере.
На телефонах `text-copy` использует `--text-ui`, `text-section` —
`--text-price`, а `text-page` — `--text-section`. Эти правила находятся сразу
под блоком размеров. Основной цвет текста — `text-stone-800`, второстепенный —
`text-stone-600`. Семейства и толщина шрифтов при этой настройке не меняются.
