# Доставка фотографий через Timeweb CDN

`lib/image-loader.ts` сохраняет локальные URL и использует CDN только для точных внутренних маршрутов с UUID, включённых в `lib/cdn-image-manifest.json` для выбранной ширины и текущей `imageVariantVersion`.

- `/media/{product}/{image}` → `https://bf6fiiksb2.cdn.twcstorage.ru/product-drafts/{product}/{image}.webp.v{version}.w{preparedImageWidth(width)}.webp`
- `/site-media/{image}` → тот же CDN, путь `product-drafts/site/{image}.webp.v{version}.w{width}.webp`.

Манифест подтверждает бакет, фактический storage_path и доступность каждого WebP через CDN. В нём только публичные идентификаторы и размеры, без секретов. Непроверенные фотографии (в том числе новые загрузки), другие бакеты, несовпадающие пути и неподтверждённые размеры остаются на `/media` или `/site-media`. Изменение версии вариантов также отключает старый список. Это намеренная консервативная совместимость без изменения загрузки и схемы БД.

Перед последующим выпуском список можно обновить в окружении с действующими серверными `DATABASE_*` переменными:

```sh
node --conditions=react-server --import tsx scripts/verify-cdn-images.ts
node --import tsx --test tests/image-cdn.test.ts
```

Скрипт выполняет только SELECT в транзакции READ ONLY и HEAD к существующему CDN; записывает только локальный JSON. Он не создаёт варианты, не загружает и не удаляет объекты. Ошибки проверки не разрешают соответствующий размер. Проверьте diff манифеста перед коммитом.

`StoreImage` используется публичными компонентами магазина. При ошибке CDN он переключает src/srcset на прежний loader с `?w=...&v=...`; следующий сбой передаётся существующему обработчику компонента. Проверки публикации и принадлежности изображений в резервных маршрутах сохранены. `next.config.ts` уже использует custom loader, повторной оптимизации через `/_next/image` нет.
