# Страница заказа и статусы Ozon

После оформления настоящего заказа покупатель получает кнопку «Мой заказ». Страница `/order/<256-bit-random-token>` открывается без регистрации. Тестовые платежи Robokassa остаются отдельными от настоящих заказов.

В карточке заказа в админке можно получить и скопировать ссылку, открыть черновик письма покупателю или заменить ссылку. Замена сразу отключает старую ссылку. Автоматическая отправка покупательских писем пока не подключена.

Страница показывает состав, фотографии опубликованных товаров, сумму, выбранный ПВЗ, номер отправления и состояние доставки. Внутренние заметки и контакты покупателя не передаются браузеру. Заголовки запрещают индексацию, общий кеш и передачу адреса страницы через Referer. Таблица `order_access` и функции её изменения доступны только серверу.

Оплаченный предзаказ показывает сохранённый срок изготовления. Неоплаченный заказ показывает срок резерва и оплату, если настоящие платежи разрешены. Проверка освобождает просроченный резерв; поздняя оплата отменённого заказа сохраняет существующий механизм ручной проверки.

## Доставка

Подтверждение заказа, упаковка, создание отправления, этикетка и передача посылки остаются за студией. Созданное отправление ещё не считается отправленным.

Фоновый процесс использует Ozon Delivery `/v1/posting/info` и `/v1/posting/status-history`. `on_way` / `in_courier_service` означают «В пути», `in_delivery_point` — «Можно забирать», `delivered` — «Получен». Статус отмены или ошибки доставки не запускает возврат оплаты или восстановление склада.

Статусы сохраняются атомарно вместе с историей заказа. Старые ответы и просроченные попытки не перезаписывают свежие сведения. Номер отправления показывается сразу после его создания. Для Ozon кнопка открывает список заказов в кабинете Ozon; публичного индивидуального URL отслеживания API не предоставляет.

## Расписание и обслуживание

Supabase `pg_cron` запускает `roota-order-shipment-sync` каждые 15 минут. `pg_net` обращается к `https://roota-liart.vercel.app/api/cron/order-shipments` с Bearer-ключом из Supabase Vault. Частые задания Vercel Cron не нужны.

Начальная настройка выполнена через `configure_roota_shipment_sync`: функция доступна только владельцу базы. Если меняется `CRON_SECRET` в Vercel, после новой публикации нужно обновить этот же ключ в Vault через данную функцию. Если меняется домен, обновите URL задания.

За запуск проверяется до 20 активных оплаченных отправлений, начиная с давно не проверявшихся. При ошибке запланирована повторная попытка, а в админке показывается причина. При большом количестве активных отправлений увеличьте размер партии или частоту запуска с учётом лимитов Ozon.

Проверка расписания: `cron.job` содержит активное задание; `net._http_response` содержит результат HTTPS-запроса. Код 401 означает несовпадение ключа. Код 503 означает ошибку проверки одного или нескольких отправлений; подробность доступна в `order_shipments.last_error`. Если Ozon не возвращает номер отправления, проверьте номер и принадлежность отправления аккаунту, которому выданы API-ключи.
