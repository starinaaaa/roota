# Изображения /delivery и /about

## Подготовка и публикация

Персонажи остаются локальными. `node --import tsx scripts/prepare-character-images.ts` создаёт lossless WebP в `public/optimized` и обновляет `lib/character-image-manifest.json`. Имена содержат SHA-256 подготовленных байтов. PNG сохраняются. Разрешение ограничено существующими максимальными CSS-контейнерами × DPR 3, пропорции и alpha сохранены. Это отдельный скрипт, обработка фотографий товаров не меняется.

Для фотографий /about используется существующий `scripts/prepare-local-images.ts`: качество и размеры сохранены. Подготовленные WebP не перекодируются при публикации в CDN:

```sh
node --conditions=react-server --env-file=<закрытый-файл-S3-окружения> --import tsx scripts/publish-static-images.ts
```

Скрипт работает только с существующим бакетом `edf40ed2-aaa8-4d8c-88e5-ddb30d2c5260`, ключами `site-static/optimized/{hash}-{width}.webp` и восемью фотографиями /about. Новые бакеты, политики и настройки CDN не создаются и не изменяются. `IfNoneMatch: *` запрещает перезапись; при повторном запуске проверяется сохранённый SHA-256. При несовпадении скрипт останавливается, а не заменяет файл с immutable URL. Старые версии не удаляются.

Перед обновлением `lib/static-image-cdn-manifest.json` все 64 файла скачиваются через CDN и проверяются по SHA-256. Неудачный запуск не изменяет манифест. Новый исходник получает новый хеш через существующий процесс подготовки; неопубликованное имя остаётся локальным. При изменении кодировщика также необходимо новое имя файла: перезапись прежнего immutable URL намеренно отвергается.

`lib/image-loader.ts` перенаправляет на CDN только подготовленные локальные имена, присутствующие в этом списке. `fallbackImageLoader` сохраняет локальные URL. AboutHero и AboutGallery используют существующий StoreImage, который при ошибке CDN заменяет src/srcset на локальные варианты. CDN товаров и его allowlist не изменены.

## Загрузка и кеш

- Верхние персонажи /delivery: eager с низким приоритетом, без preload. Нижние: native lazy. Размеры контейнеров и accessibility сохранены; повторной оптимизации подготовленных иллюстраций нет (`unoptimized`).
- AboutHero сохраняет единственный preload, fill, object-position и `sizes="100vw"`.
- Галерея не запрашивает фотографии до приближения секции на 300 px. Затем загружаются видимые слайды и по одному соседнему; уже загруженные сохраняются для циклической прокрутки. До загрузки используется прозрачный встроенный пиксель без сетевого запроса и без изменения геометрии. Embla, wheel gestures, клавиатура, анимации, подписи и порядок сохранены.
- sizes галереи учитывает реальные брейкпоинты 640/768/1024 px и промежутки 8/16/24 px.
- Для хешированных `/optimized/*` уже настроено `public, max-age=31536000, immutable`; новые объекты S3 получают такой же заголовок. Изменяемые исходные URL не получают immutable. Настройки CDN HTTP/3 и TTL 604800 не меняются.
- `getSiteContent`: прежний `unstable_cache`, ключ, тег `site`, TTL 60 s, плюс React cache для дедупликации страницы и footer в одном render. Нет cookies или данных заказов в кеше. Публикация по-прежнему вызывает `publish_site`, `revalidateTag("site", { expire: 0 })` и прежние `revalidatePath` — action не изменялся.
- `force-dynamic` на /delivery сохранён: paymentMode проверяется при запросе; корневой layout всё равно использует cookies для корзины. Общий HTML не кешируется и не содержит чужую корзину. Для статического кеширования всего маршрута потребовалось бы менять layout, что выходит за рамки задачи.
- Автоматический prefetch отключён только у информационных ссылок меню/footer и юридических ссылок. Каталог, категории и карточки сохраняют прежнее поведение.

## Проверка качества

PNG имеют RGBA/sRGB без ICC-профиля. После уменьшения lossless WebP совпадают с эталоном по alpha и RGB всех видимых пикселей; это проверяет `tests/character-images.test.ts`. Lossy quality 95 меньше, но в тонких линиях появились отличия, поэтому он не выбран.
