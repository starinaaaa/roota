# Рулетка дел

Закрытый инструмент по прямому адресу `/wheel`. В навигации и sitemap магазина ссылок нет. Страница и API возвращают `noindex, nofollow, noarchive`; данные не кешируются публично. Колесо не отправляет события в аналитику магазина, не создаёт корзину и не подключает её интерфейс. ИИ и новые сервисы не используются.

## Вход и участники

Владелец выбирает «Вход владельца» и использует существующие email и пароль. Проверяются действующая сессия Better Auth, подтверждённый email и `ADMIN_EMAILS`. Для рулетки создаётся собственная сессия с cookie `roota-wheel-owner`, ограниченной путём `/wheel`. Вход и выход не меняют сессию админки.

В меню профиля владелец создаёт одноразовую ссылку приглашения на семь дней. Передаёт её участнику самостоятельно. Токен находится во фрагменте URL, не попадает в HTTP access log и удаляется из адресной строки после открытия. БД хранит только SHA-256 токена. Участник задаёт имя, фамилию и пароль от 12 символов. Имя нормализуется для входа; точные полные тёзки должны использовать дополнительное имя или отчество. Email участника не запрашивается и письма не отправляются.

Участники хранятся в отдельных `wheel_user/account/session/verification` Better Auth. Они не могут войти в админку. Сброса пароля через email в этой версии нет. Не выдавайте новый профиль вместо старого, если нужно сохранить его задачи: восстановление доступа следует выполнять отдельно с проверкой личности.

Владелец видит список профилей в меню. Чужой список доступен ему только для чтения; изменения разрешены автору. Участники не видят каталог других пользователей. При входе прямо сказано, что владелец может читать список.

## Данные и защита

Используется действующий PostgreSQL Timeweb. Supabase не является рабочей БД сайта, поэтому новая зависимость от прежней инфраструктуры не добавляется.

Аддитивная миграция: `database/migrations/20261024_private_wheel.sql`. Выполняется один раз владельцем схемы перед выпуском приложения. Она создаёт только таблицы `wheel_*`; существующие таблицы, роли, функции магазина и данные не изменяются.

Рабочая роль `roota_app` не должна иметь `SUPERUSER` или `BYPASSRLS`. На `wheel_profile` и `wheel_task` включены `ENABLE` и `FORCE ROW LEVEL SECURITY`. Сервер после проверки сессии устанавливает `wheel.user_id` и `wheel.is_owner` через `set_config(..., true)` внутри транзакции; значения не переживают её и не передаются клиентом. Политики позволяют читать своё или, владельцу, любое; вставлять и обновлять только своё. UPDATE имеет USING и WITH CHECK. Физический DELETE задач рабочей роли не разрешён; удаление помечает `deleted_at`. Авторизация проверяется на каждом запросе API. Не развёртывать приложение с владельцем БД вместо ограниченной роли.

Generic HTTP-handler Better Auth для wheel не экспортируется: регистрация доступна только через проверку одноразового приглашения в `/wheel/api`. POST требует правильный Origin. Обёртка входа ограничивает попытки в PostgreSQL, в том числе для серверных вызовов Better Auth. Пароли и содержание задач не пишутся в диагностические сообщения.

БД содержит задачи, историю, выбранную задачу, начало выполнения и пропущенные в круге задачи. Полный резервный `pg_dump` рабочей БД должен включать новые `wheel_*` и их политики. Старый выборочный реестр переноса магазина не является резервной копией рулетки.

## Поведение

Выбор выполняет сервер через `crypto.randomInt` среди активных задач за вычетом всех пропущенных в этом круге. Завершённые, отложенные и удалённые задачи не участвуют. Перекрутка добавляет предыдущую выбранную задачу в пропущенные. При исчерпании круга пользователь явно запускает новый. Запись выбранной задачи и исключений атомарна; блокировка профиля сериализует запросы из нескольких вкладок.

«Начать» сохраняет начало и открывает спокойную карточку с кнопкой «Готово». Галочка сохраняет задачу в «Сделано», откуда её можно вернуть. Отложенные возвращаются через отдельную вкладку. Редактирование сохраняется при Enter или потере фокуса. Повтор запроса добавления с тем же requestId не создаёт дубликаты. Вставка с переносами строк включает массовый режим: до 100 задач за раз, название до 240 символов, до 1000 неудалённых задач на профиль.

Вращение длится четыре секунды с замедлением. Повторные нажатия блокируются синхронно до завершения. `prefers-reduced-motion` отключает вращение и сокращает ожидание до 180 мс. Большие списки показываются секторами без нечитаемых подписей. Список изначально свёрнут; после выбора остаётся одна основная кнопка.

## Проверка выпуска, 24 октября 2026

- TypeScript: без ошибок.
- Автотесты проекта: 128 прошли, 4 пропущены существующими условиями, ошибок нет.
- Отдельные тесты: доступность задач и исключения, попадание указателя в выбранный сектор, вставка CRLF, нормализация имени; настоящие SQL-политики проверены в PGlite.
- В изолированном PostgreSQL проверен API: вход владельца, отдельные cookies, регистрация по приглашению и запрет повторного использования, запрет чтения и правки чужих задач, просмотр владельца, добавление без дублирования при повторе, полный цикл без повторов, обновление страницы, начало/выполнение/возврат/откладывание/редактирование/удаление/выход.
- Во встроенном браузере проверены вход, массовая вставка, анимация и отключённая кнопка, начало, выполнение, экраны 390×844 и 375×667, отсутствие горизонтальной прокрутки. Это проверка размеров во встроенном браузере, не тест физического iPhone.
- В рабочей БД подтверждены FORCE RLS и ограниченная роль: без установленной личности она читает ноль задач и профилей.

## Возможное развитие

Небольшой необязательный таймер «только две минуты», один записываемый первый шаг к задаче и фильтр «сейчас мало сил». Не добавлять все настройки на главный экран: показывать их по запросу. Для дальнейшего расширения круга участников полезнее сначала добавить безопасное восстановление пароля и отзыв приглашений.
