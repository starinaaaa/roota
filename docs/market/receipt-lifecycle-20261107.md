# Чеки маркета: оплата, регистрация и выдача

Реализация для Timeweb App Platform. Продакшен не обновлялся. Локальный помощник и регистрация доходов в ФНС не входят в этот этап.

## Данные и поведение

- `market_sales.status/paid_at` фиксируют деньги; `market_receipt_jobs.state` независимо отражает чек.
- Наличные/перевод при подтверждении оплаты атомарно создают одну задачу на продажу. Повторное подтверждение не списывает остатки и не создаёт задачу заново. Склад интернет-магазина не используется.
- Робокасса остаётся на существующей фискализации. Задачи «Моего налога» для неё не создаются.
- До оплаты iPad показывает существующую заглушку Roota, после выбора способа оплаты — покупку. После оплаты показывает ожидание, ошибку/неопределённость либо подтверждённый оригинальный чек. Нет таймера скрытия: только продавец выбирает следующую покупку или заглушку. Уже полученный QR остаётся видимым при потере связи.
- Ссылка ФНС проходит allowlist HTTPS/хоста/пути без редиректов, ограничение времени и размера ответа, проверку PDF либо изображения. HTML, пустой ответ, недоступный или повреждённый документ не подтверждают выдачу.
- Сумму, позиции и время регистрации из изображения чека сверяет продавец (или будущий помощник). Система не выполняет OCR и не заявляет автоматическую сверку содержимого с продажей. Время регистрации передаётся из чека, время проверки сервер сохраняет отдельно.
- `market_inventory.receipt_name` редактируется в настройках маркета. Типы тарелок получают «Керамическая тарелка …», остальные позиции сохраняют известное фактическое название. Неизвестный вид изделия вводится продавцом.
- `market_sales.items` — снимок чековых наименований, количества, цены единицы и суммы. Робокасса, ручная подготовка и задача помощника используют его. Для набора «Сад» чековая единица — согласованный набор; состав и сумма сохраняются в снимке, распределение деталей — в allocations. Уже сохранённые продажи не переименовываются.
- История загружается страницами, хранит статус, время регистрации и ссылку; скачивание оригинала, QR PDF 40×58 мм и повторное открытие не регистрируют доход. Оригинальный PDF не подгоняется под этикетку: для Clabel CT221B предназначена именно QR-этикетка 40×58 мм.

## Протокол будущего локального помощника

`POST /api/market/receipt-jobs`, JSON, `Authorization: Bearer <MARKET_RECEIPT_HELPER_TOKEN>`. Отдельный секрет от 32 случайных символов в серверном окружении Timeweb; без него маршрут отключён. Не использовать admin cookie или NEXT_PUBLIC-переменную. Браузерные запросы с Origin запрещены; CORS не включён. Размер тела ограничен 4096 байтами. Ответы no-store.

1. `{action:"claim",worker:"macbook-1",mode:"test"}` — атомарно захватить следующую задачу; `job:null`, если задач нет. Для рабочей очереди требуется явно указать `mode:"live"`. Ответ содержит снимок items/amount/paid_at, идентификатор продажи, claim_token, idempotencyKey, срок захвата 300 секунд. Покупатель — физическое лицо, валюта RUB. Тестовые задачи никогда не должны отправляться в ФНС.
2. `{action:"submit",id:"<sale_id>",token:"<claim_token>"}` — ДО любого запроса регистрации дохода. Только первый ответ `maySubmit:true` разрешает одну отправку. Потеря ответа submit не разрешает отправку: повтор submit будет отклонён, требуется сверка. idempotencyKey стабилен для продажи, но не является обещанием поддержки идемпотентности со стороны ФНС.
3. `{action:"result",id,token,url:"https://lknpd.nalog.ru/api/v1/receipt/<inn>/<id>/print",registeredAt:"<ISO UTC из чека>"}` — сайт проверяет доступность документа и сохраняет результат. Повтор с тем же токеном/URL возвращает `registered` без повторного запроса к ФНС. Другая ссылка отклоняется. Поздний результат исходного исполнителя допускается после перехода в uncertain.
4. `{action:"error",id,token,error:"краткая причина",uncertain:true}` — записать ошибку. До submit ошибка даёт failed; после submit любая ошибка означает uncertain, даже если исполнитель передал uncertain:false. Не передавать в error пароли, токены или данные покупателя.

Захваты сериализованы блокировкой кассы и блокировкой строки; истёкший claimed может забрать другой исполнитель с новым токеном. Старый токен больше не действует. После submit автоматического повторного захвата/отправки нет: по истечении срока показывается uncertain. failed и uncertain остаются для ручной сверки, без кнопки слепого повтора. Сначала искать существующий доход в «Моём налоге», затем привязывать его оригинальный чек. Регистрация, HTTP-запрос к ФНС и проверка документа не удерживают транзакцию БД.

## Миграция и отдельный выпуск

1. Сделать резервную копию БД и проверить восстановление по действующему процессу проекта.
2. Проверить на стенде наличие базовых миграций `20261106_market.sql`, `20261106_market_manual_payments.sql`, `20261107_market_newsletter.sql`.
3. Применить `database/migrations/20261107_market_receipt_jobs.sql` перед запуском нового кода. Добавляет receipt_name и таблицу задач с правами roota_app. Старые оплаты без чеков становятся queued; старые ссылки — uncertain до проверки оригинала. Сами ссылки и снимки продаж сохраняются. Уникальный индекс запрещает привязку одного оригинального чека к разным продажам (включая вариант адреса с завершающим /). Если в старых данных есть такие дубли, миграция остановится: их нужно сначала сверить вручную, без автоматического удаления.
4. Проверить названия в market/control. Старые ссылки перепривязать через форму с временем из чека — повторный доход не создавать.
5. Развернуть проверенный код в Timeweb отдельным согласованным шагом. Секрет помощника пока оставить пустым. Будущий помощник подключается отдельно, после проверки его протокола сверки.
6. Проверить пару MacBook/iPad, тестовую наличную и переводную оплату, ожидание, ошибки и историю. Физическую печать на CT221B проверить отдельно: размер носителя 40×58 мм, масштаб 100%, без полей драйвера.

Не выполнялись публикация, рабочая фискализация, проверка физических iPad/принтера. Эмуляция iPad в Chromium проверяет интерфейс, а не гарантирует поведение Safari и Bluetooth-драйвера принтера.
