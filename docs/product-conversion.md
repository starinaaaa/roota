# Статистика товаров

В разделе «Воронка» период и товар сохраняются в URL. По умолчанию выбраны
30 дней и все товары; товары можно выбирать галочками, в том числе несколько сразу; доступны в том числе неопубликованные изделия с историей.
Общая воронка сайта остаётся доступна в режиме «Все товары».

- Просмотры карточек: уникальные браузеры, открывшие карточку за период.
- Добавили: уникальные браузеры с добавлением товара за период, включая каталог.
- Купили после добавления: браузеры из этой группы с последующим созданием
  и подтверждённой рабочей оплатой заказа с тем же товаром. Оплата может произойти
  позже выбранного периода, до момента построения отчёта.
- Конверсия: купившие после добавления / добавившие. При нулевом знаменателе — тире.
- Оплаченные заказы и проданные штуки: самостоятельные показатели по дате оплаты
  внутри выбранного периода. Поэтому они могут отличаться от группы конверсии.

Для набора выбранных товаров и в режиме «Все товары» браузер считается один раз; достаточно покупки хотя бы одного
из добавленных товаров. Суммировать показатели отдельных товаров для получения
общего числа посетителей нельзя. Для источников используется первое сохранённое
значение UTM браузера. Повторные callback оплаты не увеличивают результат.
Cookie действует 30 дней с создания, данные событий — 90 дней. Это оценка
браузеров, а не идентификация людей между устройствами. Возвраты не вычитаются
из факта состоявшейся оплаты. Исторические просмотры связываются с текущими URL
товаров на момент миграции; события для уже изменённых старых URL восстановить
однозначно нельзя. После миграции ID сохраняется при записи события.

## Выкладка

Перед запуском новой версии приложения выполнить как владелец схемы SQL-файл
`database/migrations/20261017_product_conversion.sql` на текущей
PostgreSQL-базе. Он добавляет колонку, привязывает доступную историю, создаёт
триггер, индекс и функцию отчёта. Существующие события не удаляются.
Права выполнения выдаются существующим ролям `roota_app`;
PUBLIC доступа к новым функциям не получает. При новой установке из исторического
снимка `database/schema.sql` этот файл также нужно выполнить после снимка.

Миграция проверена на отдельной PostgreSQL-базе со схемой приложения и в PGlite.
Сценарии в `tests/product-conversion.test.ts`: каталог без карточки, оплата на
следующий день, выбор из двух товаров, повторные просмотры, другой браузер,
смешанный заказ, повторные callback, тестовая оплата, смена URL, периоды и роли.

## Фильтры и исключение своего браузера

«Период → Выбрать даты» открывает поля «С» и «По включительно». Даты
интерпретируются в Europe/Moscow: 22–23 октября означает от полуночи 22-го
до полуночи 24-го, не включая последнюю границу. История хранится 90 дней;
выбор более ранних дат не восстанавливает удалённые события. Просмотры,
добавления и фактические продажи ограничены этими датами. Последующая
конверсия выбранной группы по-прежнему учитывается до момента отчёта.
Выбор сохраняется в URL (`product` повторяется для каждого товара,
`start` и `end` задают даты); старые ссылки с одним `product` работают.
Смешанный заказ учитывается один раз, количество изделий — только по выбранным товарам.

Кнопка «Не учитывать мой браузер» доступна администратору. Она исключает
события текущего `cart_session` из всех новых отчётов, включая оплаты и ошибки,
и ставит отдельную HttpOnly cookie на год. Следующие события этого браузера
не собираются; при смене `cart_session` новый ID тоже помечается исключённым.
Сами заказы и оплаты не удаляются. Другие устройства, браузеры и старые
сессии после удаления или истечения cookie нельзя надёжно связать с владельцем:
на каждом устройстве кнопку нужно нажать отдельно. Очистка cookie сбрасывает
настройку для следующих посещений, прежние исключённые ID остаются исключёнными.

Перед публикацией изменений применить
`database/migrations/20261023_analytics_filters.sql` **после** миграции
`20261017_product_conversion.sql`. Новая миграция создаёт таблицу исключений
и две функции отчётов; старые функции и данные сохраняются. Обновление приложения выполняется после применения этих миграций.

Проверки: `tests/analytics-filters.test.ts`, `tests/product-conversion.test.ts`
проверяют несколько товаров без дублей, исключение браузера во всех отчётах,
права доступа и обе границы московских календарных дней.

Список незавершённых корзин: `/admin/carts`. Подробности и порядок обновления
базы — в [unfinished-carts.md](unfinished-carts.md).
