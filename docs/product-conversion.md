# Статистика товаров

В разделе «Воронка» период и товар сохраняются в URL. По умолчанию выбраны
30 дней и все товары; доступны в том числе неопубликованные изделия с историей.
Общая воронка сайта остаётся доступна в режиме «Все товары».

- Просмотры карточек: уникальные браузеры, открывшие карточку за период.
- Добавили: уникальные браузеры с добавлением товара за период, включая каталог.
- Купили после добавления: браузеры из этой группы с последующим созданием
  и подтверждённой рабочей оплатой заказа с тем же товаром. Оплата может произойти
  позже выбранного периода, до момента построения отчёта.
- Конверсия: купившие после добавления / добавившие. При нулевом знаменателе — тире.
- Оплаченные заказы и проданные штуки: самостоятельные показатели по дате оплаты
  внутри выбранного периода. Поэтому они могут отличаться от группы конверсии.

В режиме «Все товары» браузер считается один раз; достаточно покупки хотя бы одного
из добавленных товаров. Суммировать показатели отдельных товаров для получения
общего числа посетителей нельзя. Для источников используется первое сохранённое
значение UTM браузера. Повторные callback оплаты не увеличивают результат.
Cookie действует 30 дней с создания, данные событий — 90 дней. Это оценка
браузеров, а не идентификация людей между устройствами. Возвраты не вычитаются
из факта состоявшейся оплаты. Исторические просмотры связываются с текущими URL
товаров на момент миграции; события для уже изменённых старых URL восстановить
однозначно нельзя. После миграции ID сохраняется при записи события.

## Выкладка

Перед запуском новой версии приложения выполнить как владелец схемы SQL-файл
`database/migrations/20261017_product_conversion.sql` на текущей
PostgreSQL-базе. Он добавляет колонку, привязывает доступную историю, создаёт
триггер, индекс и функцию отчёта. Существующие события не удаляются.
Права выполнения выдаются существующим ролям `roota_app`;
PUBLIC доступа к новым функциям не получает. При новой установке из исторического
снимка `database/schema.sql` этот файл также нужно выполнить после снимка.

Миграция проверена на отдельной PostgreSQL-базе со схемой приложения и в PGlite.
Сценарии в `tests/product-conversion.test.ts`: каталог без карточки, оплата на
следующий день, выбор из двух товаров, повторные просмотры, другой браузер,
смешанный заказ, повторные callback, тестовая оплата, смена URL, периоды и роли.
