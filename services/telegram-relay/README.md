# Закрытый релей уведомлений Roota

Подготовлен для узла с проверенным исходящим доступом к Telegram. Развёртывание и покупка узла пока не выполнены: прямой доступ из текущего App Platform Timeweb не прошёл ни через fetch, ни через IPv4 HTTPS. Отдельный VPS имеет другой исходящий маршрут, но его доступность необходимо проверить до признания решения рабочим.

Node.js 24, сторонних пакетов нет. Нужны TELEGRAM_RELAY_SECRET (случайный секрет минимум 32 символа), TELEGRAM_BOT_TOKEN и TELEGRAM_CHAT_ID. Хранить в закрытом окружении сервиса. Запускать непривилегированным пользователем, с автоматическим перезапуском и обновлениями безопасности. Доступ к /notify — только HTTPS через обратный прокси; порт 8080 закрыть снаружи. В прокси не писать тела и Authorization в логи.

POST /notify принимает только text и UUID key. Токен бота и единственный чат заданы на сервере, запрос не может изменить получателя. Параллельные повторы одного ключа объединяются. Постоянная очередь и захват события находятся в PostgreSQL магазина; при таймауте внешнего провайдера доставка может быть неопределённой — автоматическую повторную отправку без проверки не добавлять. GET /health раскрывает только готовность HTTP-процесса.

Перед использованием проверить /getMe с самого узла, затем одно помеченное тестовое сообщение в настроенный чат. Включать TELEGRAM_RELAY_URL=https://notify.roota.moscow/notify и TELEGRAM_RELAY_SECRET у магазина только после проверки TLS, отказа постороннему запросу и успешного теста. Не использовать публичные сторонние прокси и не передавать им токен бота. В тексте уведомлений остаются номер/сумма/статус заказа; имя, телефон, адрес и email не передаются.
